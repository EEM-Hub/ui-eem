**Responsive web design** (**RWD**) or **responsive design** is an approach to [web design](./Web_design) that aims to make web pages render well on a variety of devices and window or screen sizes from minimum to maximum display size to ensure usability and satisfaction.[[1]](./Responsive_web_design#cite_note-fluid_grid-1)[[2]](./Responsive_web_design#cite_note-Schade_2014-2)

 

A responsive design adapts the web-page layout to the viewing environment[[1]](./Responsive_web_design#cite_note-fluid_grid-1) by using techniques such as fluid proportion-based grids,[[3]](./Responsive_web_design#cite_note-3)[[4]](./Responsive_web_design#cite_note-EM_FG-4) flexible images,[[5]](./Responsive_web_design#cite_note-EM_FI-5)[[6]](./Responsive_web_design#cite_note-6) and [CSS3](./Cascading_Style_Sheets#CSS_3) [media queries](./Media_queries),[[7]](./Responsive_web_design#cite_note-ZMGflexEx-7)[[8]](./Responsive_web_design#cite_note-ZMGmediaQ-8)[[9]](./Responsive_web_design#cite_note-9) an extension of the `@media` rule,[[10]](./Responsive_web_design#cite_note-10) in the following ways:

 
- The fluid [grid](./Grid_(page_layout)#Grid_use_in_web_design) concept calls for page element sizing to be in relative units like percentages, rather than absolute units like [pixels](./Pixel) or [points](./Point_(typography)).[[4]](./Responsive_web_design#cite_note-EM_FG-4)
- Flexible images are also sized in relative units, so as to prevent them from displaying outside their containing [element](./HTML_element).[[5]](./Responsive_web_design#cite_note-EM_FI-5)ref name="AI" / 
- Media queriesref name="ZMGmediaQ" /ref name="ZMGflexEx" / allow the page to use different CSS style rules based on characteristics of the device the site is being displayed on, e.g. width of the rendering surface (browser window width or physical display size).
- Responsive layouts automatically adjust and adapt to any device screen size, whether it is a desktop, a laptop, a tablet, or a mobile phone.

 

Responsive web design became more important as users of [mobile devices](./Mobile_device) came to account for the majority of website visitors.[[11]](./Responsive_web_design#cite_note-11)[[12]](./Responsive_web_design#cite_note-12) In 2015, for instance, Google announced [Mobilegeddon](./Mobilegeddon) and started to boost the page ranking of mobile-friendly sites when searching from a mobile device.[[13]](./Responsive_web_design#cite_note-13)

 

Responsive web design is an example of [user interface plasticity](./User_interface_plasticity).[[14]](./Responsive_web_design#cite_note-14)

  

## Challenges, and other approaches

 

Luke Wroblewski has summarized some of the responsive and mobile design challenges and created a catalog of multi-device layout patterns.[[15]](./Responsive_web_design#cite_note-15)[[16]](./Responsive_web_design#cite_note-RWD-16)[[17]](./Responsive_web_design#cite_note-17) He suggested that, compared with a simple responsive web design approach, device experience or RESS (responsive web design with server-side components) approaches can provide a user experience that is better optimized for mobile devices.[[18]](./Responsive_web_design#cite_note-RESS-18)[[19]](./Responsive_web_design#cite_note-19)[[20]](./Responsive_web_design#cite_note-20) Server-side CSS generator implementation of stylesheet languages like [Sass](./Sass_(stylesheet_language)) can be part of such an approach. Google has recommended responsive design for smartphone websites over other approaches.[[21]](./Responsive_web_design#cite_note-21)

 

Although many publishers have implemented responsive designs, one challenge for responsive design adoption was that some [banner advertisements](./Web_banner) and videos were not fluid.[[22]](./Responsive_web_design#cite_note-22) However, [search advertising](./Search_advertising) and (banner) [display advertising](./Display_advertising) came to support specific device platform targeting and different advertisement size formats for desktop, smartphone, and basic mobile devices. Different [landing page](./Landing_page) [URLs](./URL) have been used for different platforms,[[23]](./Responsive_web_design#cite_note-23) or [Ajax](./Ajax_(programming)) has been used to display different advertisement variants on a page.[[24]](./Responsive_web_design#cite_note-SSDD-24)[[16]](./Responsive_web_design#cite_note-RWD-16)[[25]](./Responsive_web_design#cite_note-25) CSS tables permitted hybrid fixed and fluid layouts.[[26]](./Responsive_web_design#cite_note-26)

 

There have been many ways of validating and testing responsive web designs,[[27]](./Responsive_web_design#cite_note-27) ranging from mobile site validators and mobile emulators to simultaneous testing tools like [Adobe Edge Inspect](./Adobe_Edge_Inspect).[[28]](./Responsive_web_design#cite_note-28) The Chrome, Firefox and Safari browsers and developer tools have offered responsive design viewport resizing tools, as do third parties.[[29]](./Responsive_web_design#cite_note-29)[[30]](./Responsive_web_design#cite_note-30)

 

## History

 Further information: [History of the World Wide Web](./History_of_the_World_Wide_Web) and [Web 2.0](./Web_2.0) 

The W3C specification of HTML+ stated that websites have to be rendered according to the user preferences.[[31]](./Responsive_web_design#cite_note-31) The customization of web page layout was lacking however. Many web developers resorted to ordinary HTML tables as a way to customize the layout and bring some basic responsiveness to their websites at the same time.

 

First major site to feature a layout that adapts in a non-trivial manner to browser viewport width was *[Audi](./Audi).com* launched in late 2001,[[32]](./Responsive_web_design#cite_note-32)  created by a team at [Razorfish](./Razorfish_(company)) consisting of Jürgen Spangl and [Jim Kalbach](./Jim_Kalbach?action=edit&redlink=1) (information architecture), Ken Olling (design), and Jan Hoffmann (interface development). Limited browser capabilities meant that for Internet Explorer, the layout could adapt dynamically in the browser whereas, for Netscape, the page had to be reloaded from the server when resized.

 

Cameron Adams created a demonstration in 2004.[[33]](./Responsive_web_design#cite_note-33)  By 2008, a number of related terms such as "flexible", "liquid",[[34]](./Responsive_web_design#cite_note-34) "fluid", and "elastic" were being used to describe layouts. CSS3 media queries were almost ready for prime time in late 2008/early 2009.[[35]](./Responsive_web_design#cite_note-35) Ethan Marcotte coined the term *responsive web design*[[36]](./Responsive_web_design#cite_note-36)—and defined it to mean fluid grid / flexible images / media queries—in a May 2010 article in *[A List Apart](./A_List_Apart)*.[[1]](./Responsive_web_design#cite_note-fluid_grid-1) He described the theory and practice of responsive web design in his brief 2011 book titled *Responsive Web Design*. Responsive design was listed as #2 in Top Web Design Trends for 2012 by [.net magazine](./.net_(magazine)) after [progressive enhancement](./Progressive_enhancement) at #1.[[37]](./Responsive_web_design#cite_note-37)

 

[Mashable](./Mashable) called 2013 the Year of Responsive Web Design.[[38]](./Responsive_web_design#cite_note-mashable_2013-38)

 

## Related concepts

 See also: [Unobtrusive JavaScript](./Unobtrusive_JavaScript) and [Progressive enhancement](./Progressive_enhancement) 

**Mobile-first design**boldface per [[WP:R#PLA]] and [progressive enhancement](./Progressive_enhancement) are related concepts that predate responsive web design.[[39]](./Responsive_web_design#cite_note-39) Browsers of basic mobile phones do not understand JavaScript or [media queries](./Media_queries), so a recommended practice was to create a basic web site and enhance it for [smartphones](./Smartphone) and [personal computers](./Personal_computer), rather than rely on [graceful degradation](./Graceful_degradation) to make a complex, image-heavy site work on mobile phones.[[40]](./Responsive_web_design#cite_note-40)[[41]](./Responsive_web_design#cite_note-Firtman-41)[[42]](./Responsive_web_design#cite_note-42)[[43]](./Responsive_web_design#cite_note-43)

 

[User interface plasticity](./User_interface_plasticity) is the capacity of a [user interface](./User_interface) to withstand variations of both the system's physical characteristics and the environment while preserving [usability](./Usability).[[44]](./Responsive_web_design#cite_note-44)
